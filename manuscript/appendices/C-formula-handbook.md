## Chapter 2 — How to Think Like a System Designer

*From §2.5.1*

::: formula
**Allowed downtime for an availability target**

| Symbol | Meaning | Units |
|---|---|---|

| $A$ | Availability target, as a fraction | dimensionless (e.g. 0.9995) |
| $T_{period}$ | Length of the measurement period | minutes |
:::

*From §2.6.1*

::: formula
**Service demand, the utilization law and the bottleneck bound**

$$D_i = V_i \times S_i \qquad U_i = X \times D_i \qquad X_{max} = \frac{c_i}{D_{max}}$$

| Symbol | Meaning | Units |
|---|---|---|
| $D_i$ | Service demand: total busy time one request places on resource $i$ | seconds per request |
| $V_i$ | Visits: how many times one request uses resource $i$ | visits per request |
| $S_i$ | Service time per visit to resource $i$ | seconds per visit |
| $U_i$ | Utilization of resource $i$, per unit of capacity | fraction (0–1) |
| $X$ | System throughput | requests per second |
| $c_i$ | Number of parallel units of resource $i$ (e.g. cores) | units |
| $X_{max}$ | Maximum throughput, set by the resource with the largest demand per unit | requests per second |

The utilization law for a resource with $c_i$ parallel units is $U_i = X \times D_i / c_i$. The bottleneck is the resource with the largest $D_i / c_i$.
:::

*From §2.6.1*

::: formula
**Little's Law (concurrency)**

$$L = \lambda \times W$$

| Symbol | Meaning | Units |
|---|---|---|
| $L$ | Average number of requests in the system (or holding a resource) at once | requests |
| $\lambda$ | Average arrival rate | requests per second |
| $W$ | Average time each request spends in the system (or holds the resource) | seconds |

Little's Law holds for any stable system, regardless of the arrival pattern [Little 1961]. Full treatment in §4.11.
:::

*From §4.6.1*

::: formula
**Probability that at least one of $N$ independent components fails**

*From §4.6.2*

::: formula
**Union (inclusion–exclusion) and intersection**

$$P(A \cup B) = P(A) + P(B) - P(A \cap B) \qquad P(A \cap B) = P(A) \times P(B \mid A)$$

| Symbol | Meaning | Units |
|---|---|---|
| $P(A \cup B)$ | Probability that $A$ or $B$ (or both) happens | dimensionless |
| $P(A \cap B)$ | Probability that both happen | dimensionless |

*From §4.6.3*

::: formula
**Expected value and linearity of expectation**

$$E[X] = \sum_i x_i\,P(X = x_i) \qquad E[X_1 + X_2 + \cdots + X_N] = E[X_1] + \cdots + E[X_N]$$

| Symbol | Meaning | Units |
|---|---|---|
| $X$ | A random quantity (failures, latency, cost) | units of the quantity |
| $x_i$ | A possible value of $X$ | units of the quantity |

*From §4.6.4*

::: formula
**Binomial probability of exactly $k$ failures**

$$P(K = k) = \binom{N}{k} p^k (1-p)^{N-k}, \qquad \binom{N}{k} = \frac{N!}{k!\,(N-k)!}, \qquad E[K] = Np$$

| Symbol | Meaning | Units |
|---|---|---|
| $N$ | Number of independent components (trials) | count |
| $k$ | Number of failures we ask about | count |
| $p$ | Per-component failure probability in the period | dimensionless |
| $\binom{N}{k}$ | Number of ways to choose which $k$ components fail ("$N$ choose $k$") | count |
| $E[K]$ | Expected number of failures | count |

*From §4.10.2*

::: formula
**M/M/1 results**

$$\rho = \frac{\lambda}{\mu} \qquad W = \frac{1}{\mu - \lambda} = \frac{S}{1 - \rho} \qquad W_q = \frac{\rho}{\mu - \lambda} \qquad L = \frac{\rho}{1 - \rho} \qquad L_q = \frac{\rho^2}{1 - \rho}$$

| Symbol | Meaning | Units |
|---|---|---|
| $\lambda$ | Average arrival rate | jobs/second |
| $\mu$ | Average service rate of the server | jobs/second |
| $S = 1/\mu$ | Average service time | seconds |
| $\rho$ | Utilization: fraction of time the server is busy (must be $< 1$) | dimensionless |
| $W$ | Average time in system (waiting + service), i.e. response time | seconds |
| $W_q$ | Average time waiting in the queue before service starts | seconds |
| $L$ | Average number of jobs in the system | jobs |
| $L_q$ | Average number of jobs waiting in the queue | jobs |
:::

## Chapter 5 — Computer Architecture

*From §5.3.2*

::: formula
**CPU execution time (the "iron law")**

$$T_{CPU} = N_{instr} \times CPI \times t_{cycle} = \frac{N_{instr} \times CPI}{f}$$

| Symbol | Meaning | Units |
|---|---|---|

| $CPI$ | Average clock cycles per instruction (its inverse is IPC, instructions per cycle) | cycles/instruction |

:::

*From §5.4.4*

::: formula
**Address decomposition in a set-associative cache**

$$S = \frac{C}{B \times W}, \qquad \text{offset bits} = \log_2 B, \qquad \text{index bits} = \log_2 S$$

$$\text{set index} = \left\lfloor \frac{A}{B} \right\rfloor \bmod S, \qquad \text{tag} = \left\lfloor \frac{A}{B \times S} \right\rfloor$$

| Symbol | Meaning | Units |
|---|---|---|
| $C$ | Cache capacity | bytes |
| $B$ | Line (block) size | bytes |
| $W$ | Associativity (ways per set) | lines |
| $S$ | Number of sets | sets |
| $A$ | Memory address | byte address |
| tag | High-order address bits stored with the line to identify it | — |
:::

*From §5.4.5*

::: formula
**Average memory access time (AMAT), applied recursively to each level**

$$AMAT = t_{L1} + m_{L1} \times \bigl(t_{L2} + m_{L2} \times (t_{L3} + m_{L3} \times t_{mem})\bigr)$$

| Symbol | Meaning | Units |
|---|---|---|
| $t_{L1}, t_{L2}, t_{L3}$ | Hit time at each cache level | ns |
| $t_{mem}$ | DRAM access time | ns |
| $m_{L1}$ | Fraction of all accesses that miss L1 | dimensionless (0–1) |
| $m_{L2}, m_{L3}$ | **Local** miss rate: fraction of accesses *reaching* that level that miss it | dimensionless (0–1) |
:::

*From §5.6.1*

::: formula
**HDD access time**

$$T_{access} = T_{seek} + T_{rot} + T_{transfer}, \qquad T_{rot} = \frac{1}{2} \times \frac{60}{RPM}, \qquad T_{transfer} = \frac{S}{R}$$

$$IOPS_{random} \approx \frac{1}{T_{access}}$$

| Symbol | Meaning | Units |
|---|---|---|
| $T_{seek}$ | Average time to move the head to the target track | ms |
| $T_{rot}$ | Average rotational latency: half a revolution | ms |
| $RPM$ | Spindle speed | revolutions per minute |
| $S$ | Size of the request | bytes |
| $R$ | Sustained media transfer rate | bytes/second |
| $IOPS_{random}$ | Random I/O operations per second for one outstanding request | operations/second |
:::

| Symbol | Meaning | Units |
|---|---|---|

| $C$ | Raw flash capacity | bytes |

| Symbol | Meaning | Units |

::: formula

| Symbol | Meaning | Units |

*From §7.4.2*

| Symbol | Meaning | Units |
|---|---|---|

*From §7.7.5*

::: formula
**Retransmission timeout (RFC 6298)**

On each new RTT sample $R$ (after the first):

$$\text{RTTVAR} \leftarrow (1-\beta)\,\text{RTTVAR} + \beta\,|\text{SRTT} - R|$$
$$\text{SRTT} \leftarrow (1-\alpha)\,\text{SRTT} + \alpha\,R$$
$$\text{RTO} = \text{SRTT} + \max(G,\ 4\,\text{RTTVAR})$$

| Symbol | Meaning | Units |
|---|---|---|
| $R$ | Latest measured round-trip time | ms |
| SRTT | Smoothed (exponentially averaged) RTT | ms |
| RTTVAR | Smoothed RTT variation | ms |
| $\alpha, \beta$ | Smoothing gains, $1/8$ and $1/4$ | dimensionless |
| $G$ | Clock granularity | ms |
| RTO | Retransmission timeout; RFC 6298 says round up to at least 1 s | ms |
:::

*From §7.7.7*

::: formula
**CUBIC window growth**

$$W(t) = C\,(t - K)^3 + W_{\max}, \qquad K = \sqrt[3]{\frac{W_{\max}\,(1-\beta)}{C}}$$

| Symbol | Meaning | Units |
|---|---|---|
| $W(t)$ | Congestion window $t$ seconds after the last loss | segments |
| $W_{\max}$ | Window just before the last loss | segments |
| $\beta$ | Multiplicative decrease factor; window becomes $\beta W_{\max}$ after loss (0.7) | dimensionless |
| $C$ | Scaling constant (0.4) | segments/s³ |
| $K$ | Time to climb back to $W_{\max}$ | s |
:::

*From §7.15.1*

::: formula
**One-hop delay**

$$d_{\text{hop}} = \underbrace{\frac{D}{v}}_{\text{propagation}} + \underbrace{\frac{L}{R}}_{\text{transmission}} + d_{\text{queue}} + d_{\text{proc}}$$

| Symbol | Meaning | Units |
|---|---|---|
| $D$ | Physical length of the link | m (or km) |
| $v$ | Signal speed in the medium: about $2 \times 10^8$ m/s in optical fiber (roughly two-thirds of $c$) | m/s |
| $L$ | Packet size | bits |
| $R$ | Link rate (bandwidth) | bits/s |
| $d_{\text{queue}}$ | Queuing delay: bytes waiting ahead ÷ link rate | s |
| $d_{\text{proc}}$ | Processing delay: microseconds in software, sub-microsecond in switch hardware | s |
:::

*From §7.15.2*

::: formula
**Window-limited throughput and the bandwidth-delay product (BDP)**

$$\text{Throughput} \le \frac{W}{\text{RTT}} \qquad\qquad \text{BDP} = R \times \text{RTT}$$

| Symbol | Meaning | Units |
|---|---|---|
| $W$ | Effective window, $\min(\text{cwnd}, \text{rwnd})$ | bytes |
| RTT | Round-trip time | s |
| $R$ | Bottleneck link rate | bits/s (divide by 8 for bytes/s) |
| BDP | Data that must be in flight to keep the link full | bits or bytes |
:::

*From §7.15.3*

::: formula

$$\text{Throughput} \le \frac{\text{MSS}}{\text{RTT}} \times \frac{C}{\sqrt{p}}$$

| Symbol | Meaning | Units |
|---|---|---|
| MSS | Maximum segment size | bits (or bytes, for bytes/s) |
| RTT | Round-trip time | s |
| $p$ | Packet loss probability | dimensionless |
| $C$ | Constant, $\sqrt{3/2} \approx 1.22$ for periodic loss with every packet ACKed | dimensionless |

## Chapter 9 — Real-Time Communication

*From §9.3.1*

::: formula
**Short-polling request rate**

$$R = \frac{N}{T}$$

| Symbol | Meaning | Units |
|---|---|---|
| $R$ | Request rate arriving at the servers | requests/second |
| $N$ | Number of concurrently active (polling) clients | clients |
| $T$ | Polling interval | seconds |
:::

*From §9.3.1*

::: formula
**Fraction of wasted (empty) polls and added latency**

If updates for a client arrive as a Poisson process with rate $\lambda$, the probability that a given interval contains no update is

$$P_{\text{empty}} = e^{-\lambda T} \approx 1 - \lambda T \quad (\text{when } \lambda T \ll 1)$$

and the average delay between an event occurring and the client seeing it is

$$D_{\text{avg}} = \frac{T}{2} + t_{\text{rtt}}$$

| Symbol | Meaning | Units |
|---|---|---|
| $P_{\text{empty}}$ | Fraction of polls that return nothing | dimensionless (0–1) |
| $\lambda$ | Average update rate per client | events/second |
| $T$ | Polling interval | seconds |
| $D_{\text{avg}}$ | Average notification delay | seconds |
| $t_{\text{rtt}}$ | Network round-trip time for one poll | seconds |
:::

*From §9.4.1*

::: formula
**Long-polling request rate**

With Poisson events at rate $\lambda$ per client and hold timeout $T_h$, each request lasts $\min(T_h, X)$ where $X$ is the time to the next event. Its mean is

$$E[\text{duration}] = \frac{1 - e^{-\lambda T_h}}{\lambda}, \qquad R = \frac{N}{E[\text{duration}]}, \qquad C_{\text{open}} \approx N$$

| Symbol | Meaning | Units |
|---|---|---|
| $\lambda$ | Average update rate per client | events/second |
| $T_h$ | Server hold timeout | seconds |
| $E[\text{duration}]$ | Mean lifetime of one long-poll request | seconds |
| $N$ | Number of connected clients | clients |
| $R$ | Request rate at the servers | requests/second |
| $C_{\text{open}}$ | Concurrently open requests (Little's Law: $R \times E[\text{duration}]$) | requests |
:::

*From §9.6.3*

::: formula
**WebSocket framing overhead per frame**

$$H = 2 + L_{\text{ext}} + 4m, \qquad L_{\text{ext}} = \begin{cases} 0 & n \le 125 \\ 2 & 126 \le n \le 65{,}535 \\ 8 & n \ge 65{,}536 \end{cases}$$

| Symbol | Meaning | Units |
|---|---|---|
| $H$ | Header bytes per frame | bytes |
| $n$ | Payload length | bytes |
| $L_{\text{ext}}$ | Extended-length bytes | bytes |
| $m$ | 1 if masked (client→server), 0 otherwise | dimensionless |
:::

::: formula
**Per-participant bandwidth by topology**

| Topology | Upload per participant | Download per participant | Server work |
|---|---|---|---|
| Mesh | $(N-1)\,b$ | $(N-1)\,b$ | none |
| SFU | $b$ (or $\approx 1.5b$–$2b$ with simulcast) | $(N-1)\,b$ (less if receivers get lower layers) | forward $N(N-1)$ streams |

## Chapter 10 — Security Fundamentals for System Designers

*From §10.3.5*

::: formula
**Qualitative risk score**

$$R = L \times I$$

| Symbol | Meaning | Units |
|---|---|---|
| $R$ | Risk score used to rank threats | dimensionless (1–9 on a 3-point scale) |
| $L$ | Likelihood that the threat is exploited within the planning horizon (1 = unlikely, 2 = plausible, 3 = expected) | ordinal score |
| $I$ | Impact if exploited (1 = minor, 2 = serious, 3 = severe: data breach, financial loss, regulatory) | ordinal score |
:::

*From §10.4.1*

::: formula
**Birthday bound for hash collisions**

$$P_{\text{collision}} \approx \frac{k^2}{2^{\,n+1}}$$

| Symbol | Meaning | Units |
|---|---|---|
| $k$ | Number of distinct inputs hashed | count |
| $n$ | Digest length | bits |
| $P_{\text{collision}}$ | Probability that at least two of the $k$ digests are equal (valid while $P \ll 1$) | probability |

Consequence: an $n$-bit hash offers about $n/2$ bits of collision resistance, because $P$ approaches $1/2$ when $k \approx 2^{n/2}$.
:::

*From §10.4.2*

::: formula
**Random-nonce collision probability for AES-GCM**

$$P_{\text{reuse}} \approx \frac{q^2}{2^{97}}$$

| Symbol | Meaning | Units |
|---|---|---|
| $q$ | Number of messages encrypted under one key with random 96-bit nonces | messages |
| $P_{\text{reuse}}$ | Probability that any two of them share a nonce (birthday bound with $n = 96$) | probability |
:::

*From §10.4.7*

::: formula
**Entropy of a uniformly random secret**

$$H = L \cdot \log_2 N$$

| Symbol | Meaning | Units |
|---|---|---|
| $H$ | Entropy: the number of bits an attacker must effectively guess | bits |
| $L$ | Length of the secret | symbols |
| $N$ | Number of equally likely choices per symbol | symbols |

Valid only when every symbol is chosen independently and uniformly at random — true for machine-generated tokens, false for human-chosen passwords.
:::

*From §10.6.2*

::: formula
**Expected offline brute-force time**

$$T = \frac{S}{2 \cdot R \cdot G}$$

| Symbol | Meaning | Units |
|---|---|---|
| $T$ | Expected time to find one password (average: half the space) | seconds |
| $S$ | Size of the search space: $N^L$ for random passwords, or the size of the attacker's ranked wordlist up to the target | candidates |
| $R$ | Guesses per second per attacking device for this hash function and cost | guesses/s/device |
| $G$ | Number of attacking devices (GPUs) | devices |

Salting means $T$ is paid **per user**; without salts, one pass covers all users.
:::

*From §10.8*

::: formula
**Credential misuse window**

$$W = \begin{cases} T_{\text{detect}} + T_{\text{rotate}} & \text{long-lived credential} \\ \min(T_{\text{TTL}},\ T_{\text{detect}} + T_{\text{revoke}}) & \text{short-lived credential} \end{cases}$$

| Symbol | Meaning | Units |
|---|---|---|
| $W$ | Time during which a leaked credential remains usable | hours |
| $T_{\text{detect}}$ | Time from leak to detection | hours |
| $T_{\text{rotate}}, T_{\text{revoke}}$ | Time to rotate or revoke after detection | hours |
| $T_{\text{TTL}}$ | Lifetime of a short-lived credential | hours |
:::

*From §10.9.2*

::: formula
**KMS request rate under envelope encryption**

$$Q_{\text{KMS}} = \frac{\lambda_{\text{obj}}}{B}$$

| Symbol | Meaning | Units |
|---|---|---|
| $Q_{\text{KMS}}$ | KMS requests generated | requests/s |
| $\lambda_{\text{obj}}$ | Rate of objects (or records) encrypted or decrypted | objects/s |
| $B$ | Objects protected per KMS call (1 for a DEK per object; larger with DEK caching or per-batch keys) | objects/request |

*From §10.11*

| Symbol | Meaning | Units |
